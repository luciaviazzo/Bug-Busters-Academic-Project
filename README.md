# Sistema Backend con Persistencia Políglota

## Propósito del proyecto

Este repositorio corresponde a un proyecto académico desarrollado en el marco de la carrera **Tecnicatura Universitaria en Programación / Licenciatura en Informática** de la Universidad Nacional de Quilmes.

El objetivo principal del proyecto fue aplicar en un caso práctico los conocimientos adquiridos en la materia **Estrategias de Persistencia**, trabajando de manera colaborativa para diseñar y desarrollar una solución backend a un problema propuesto por la cátedra, simulando un entorno de desarrollo profesional.

La aplicación está ambientada en un universo ficticio y fue evolucionando a lo largo de distintas etapas, incorporando nuevas tecnologías y estrategias de persistencia a medida que se avanzaba en los contenidos de la materia.

---

## Descripción general

El sistema fue desarrollado utilizando **Java + Spring Boot** bajo una arquitectura desacoplada y modular, integrando múltiples motores de persistencia según las necesidades de cada caso de uso.

Cada etapa del proyecto estuvo enfocada en investigar, implementar y comparar distintas tecnologías de almacenamiento de datos, aplicando criterios de escalabilidad, rendimiento y separación de responsabilidades.

---

## Habilidades desarrolladas

Durante el desarrollo de este proyecto se trabajó en:

- Desarrollo backend en Java aplicando principios de **Programación Orientada a Objetos (OOP)**.
- Implementación de estrategias de persistencia integrando bases de datos **SQL** y **NoSQL**.
- Diseño de arquitectura en capas (**Controller – Service – DAO – Model**) para desacoplar la lógica de negocio de la persistencia.
- Aplicación de buenas prácticas:
  - Patrones de diseño
  - Clean Code
  - Principios SOLID
  - Testing automatizado
- Desarrollo de **API REST** y uso de **DTOs** para desacoplar el modelo de dominio.
- Trabajo colaborativo utilizando **Git/GitHub** y workflow **GitFlow**.
- Modelado de dominio y separación de responsabilidades.

## Arquitectura

El proyecto fue diseñado siguiendo principios de **Clean Architecture**, priorizando:

- Escalabilidad
- Mantenibilidad
- Bajo acoplamiento
- Separación de responsabilidades

La estructura del sistema permite desacoplar la lógica de negocio de los mecanismos de persistencia, facilitando la incorporación de nuevas tecnologías y estrategias de almacenamiento.
